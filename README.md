# dialogue-to-blog-skill

一个用于指导 AI 编程助手（如 Antigravity / Claude Code 等 Agent）将人机真实技术对话记录，整理并转换为高质量工程技术博客的 Skill 规范。

---

## 背景与问题

在使用 AI 助手辅助写代码、调试系统或探索技术的过程中，常有将当次对话沉淀为博客文章的需求。但大语言模型在生成文章时普遍存在以下问题：

1. **脱离真实交互**：丢弃了调试过程中实际运行的命令、硬件参数、具体报错与探索波折，容易生成空洞的通用科普文。
2. **浮夸与空话泛滥**：习惯性填充“颠覆性”、“划时代”、“深入浅出”、“不可否认的是”等公关词汇与总结模板。
3. **细节被过度概括**：在遇到多项机制或复杂对比时，习惯擅自精简，使用“等等”、“诸如此类”略去具体技术实现。

本项目提供了一套标准的 Skill 规范，旨在约束 AI Agent 按照工程师记录笔记的客观文风，全量、真实地复盘每一次技术探索。

---

## 核心设计规则

1. **真实骨架原则（对话即大纲）**
   * 以交互中的实际步骤展开（环境识别 -> 报错排查 -> 解决验证 -> 底层探索）。
   * 必须保留真实的设备型号、内核属性、端口号、测量数据与终端输入输出，杜绝使用虚拟占位符。

2. **“疑问-原理”成对解析范式**
   * 所有讨论章节统一采用双层结构：
     * **疑问是什么**：准确说明机主在对话中提出的具体现象、疑问或追问；
     * **具体底层原理是什么**：从系统内核、硬件总线、网络协议、运行时虚拟机或安全机制的底层逻辑切入解答。

3. **点对点绝对全覆盖**
   * 对话中讨论了几个疑问，文章就必须对应建立几个独立小节；
   * 对话中列举的技术要点（如 Root 的具体权限、各系统的优劣对比），必须逐项完整写出，严禁擅自删减或合并。

4. **语言平实，彻底去 AI 腔**
   * 严格过滤无意义的形容词与公关套话；
   * 采用客观陈述事实、呈现数据、解析代码的平实技术语言。

## 安装与使用方法

### 在 Antigravity CLI 中使用

1. 将本仓库克隆至本地：
   ```bash
   git clone https://github.com/eryuemu/dialogue-to-blog-skill.git ~/.gemini/config/skills/dialogue-to-blog-skill
   ```
2. 或者在你的项目工作区通过软链接接入：
   ```bash
   ln -s /path/to/dialogue-to-blog-skill ~/.gemini/config/skills/dialogue-to-blog-skill
   ```
3. 在与 AI 助手的日常会话中，完成某项技术调试后，直接输入自然语言指令即可触发本 Skill：
   > “根据我们刚才的聊天记录和调试过程，整理一篇技术博客发布到我的博客目录。”

AI 助手将自动加载本 Skill 的 SOP 流程，扫描上下文、建立全覆盖 Checklist、装配 Frontmatter、本地测试验证并交付文章。
